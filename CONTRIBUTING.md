# Contributing

This file contains documentation about contributing to this project.

## Develop locally

After cloning the repository, install the project and its development
dependencies with [`uv`](https://docs.astral.sh/uv/), which creates `.venv/`:

```shell
$ uv sync --all-extras --dev
$ source .venv/bin/activate  # optional; otherwise prefix commands with `uv run`
```

### Pre-commit hooks

Install pre-commit hooks to ensure code quality and consistency:

```shell
$ pre-commit install
```

### Test

To run the unit tests, use the following command:

```shell
$ uv run pytest
```

This also runs the `>>>` examples in `README.md` and in docstrings under `src/`
as doctests, and enforces 80% coverage.

CI ([ci.yaml](.github/workflows/ci.yaml)) additionally runs:

```shell
$ uv run ruff check src tests
$ uv run ruff format --check src tests
$ uv run pyrefly check
$ find docs/notebooks/*.ipynb -maxdepth 1 -type f | xargs -L1 uv run jupyter nbconvert --to notebook --execute
```

To run the pre-commit hooks on all files, run:

```shell
$ pre-commit run --all-files
```

### Documentation

The documentation site is built with [mkdocs](https://www.mkdocs.org/) from
`docs/` (see [mkdocs.yml](mkdocs.yml)) and deployed to GitHub Pages on every push
to `main` ([pages.yaml](.github/workflows/pages.yaml)); `README.md` is copied to
the site's home page (locally, `docs/index.md` is a placeholder). Preview it
locally with:

```shell
$ uv run mkdocs serve
```

Code examples in `docs/*.md` are not tested, so check them by hand when you
change the API they use.

## How to release

This section describes how to release the package in this project.

### Prerequisites

* Push and merge rights for this repo,
  [proteingym-base](https://github.com/ProteinGym/proteingym-base),
  also referred to as the *upstream*.
* A UNIX system that has:
  - `git` able to push to upstream

### Release

We use hatch to [version](https://hatch.pypa.io/latest/version/) the project.
Before releasing, you decide which semantic version segment you want to
release, like:

| Segment  | New version | 
| -------- | ----------- |
| release  | 1.0.0       |
| major    | 2.0.0       |
| minor    | 1.1.0       |
| patch    | 1.0.1       |
| rc       | 1.0.0rc0    |

> See [docs](https://hatch.pypa.io/latest/version/) for full details.

Then, you run the following

``` bash
$ hatch version release|major|minor|patch|rc
$ VERSION=$(hatch version)
$ git checkout -b release/v$VERSION
$ git add src/proteingym/base/__about__.py
$ git commit -m "Release v$VERSION"
$ git tag v$VERSION
$ git push --set-upstream origin release/v$VERSION
$ git push --tags
```

The tag push triggers the release CI, which creates a release for the tag with
autogenerated release notes. After the new release appears in
[Github](https://github.com/ProteinGym/proteingym-base/releases), copy the release
notes to create a PR for the release branch with the release commit as the title
and the release notes as the body. Assign a colleague to review the PR and merge
it after approval.
